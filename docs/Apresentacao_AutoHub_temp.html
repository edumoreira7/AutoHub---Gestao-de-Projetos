Guia de execução e apresentação

Como iniciar o projeto, explicar a API e demonstrar as Histórias 1 a 5

1. Executar no VS Code

No computador da faculdade, instale Node.js 22.12 ou superior, abra no VS Code a pasta raiz do AutoHub e use dois terminais PowerShell.

Terminal 1 · API

cd backend
npm install
npm run start:dev

Terminal 2 · Interface

cd frontend
npm install
npm run dev

Abra no navegador a URL informada pelo Vite, normalmente http://localhost:5173 ou http://localhost:5174. A API fica em http://localhost:3000. Se o terminal disser que npm não é reconhecido, instale Node.js e reinicie o VS Code.

2. Qual API usamos?

O projeto usa uma API REST própria, desenvolvida com NestJS. Não é uma API externa. O frontend envia requisições HTTP com dados JSON; o backend valida as informações, executa a operação e devolve uma resposta com sucesso, dados ou mensagem de erro.

Método e rotaFinalidade
POST /clientesCadastrar cliente.
GET /clientes?nome=&cpf=&telefone=Consultar clientes por um ou mais critérios.
POST /veiculosCadastrar veículo com clienteId do proprietário.
GET /veiculos?placa=&marca=&modelo=Consultar veículos e retornar o proprietário.
POST /ordens-servicoCriar ordem vinculada a um veículo existente.
Persistência atual: para permitir executar o sistema sem MongoDB instalado, os dados são gravados localmente em backend/data/clientes.json, veiculos.json e ordens-servico.json. Esses arquivos são ignorados pelo Git, portanto não acompanham o projeto ao copiá-lo para outro computador; cadastre dados de demonstração novamente nesse caso.

3. As cinco histórias

HU1 · Cadastrar cliente

O funcionário informa nome completo, CPF, telefone e e-mail. O sistema valida os campos, exige CPF com 11 dígitos e telefone com 11 dígitos, impede CPF ou e-mail duplicados, salva o cliente e informa sucesso ou erro. A regra atual do CPF verifica quantidade e formato, não os dígitos verificadores.

HU2 · Consultar clientes

Permite pesquisar por nome, CPF ou telefone, exibe os dados encontrados e informa quando não há correspondência. O botão Mostrar todos consulta a API sem filtros.

HU3 · Cadastrar veículo

Registra placa, marca, modelo, ano e cor. O funcionário seleciona um cliente existente; o sistema envia o identificador do cliente, impede vínculo inexistente e informa o resultado do cadastro.

HU4 · Consultar veículos

Permite buscar por placa, marca ou modelo. Os resultados mostram os dados do veículo e o cliente proprietário. Também há mensagem para busca sem resultados e botão Mostrar todos.

HU5 · Criar ordem de serviço

Registra descrição dos serviços e data, exigindo a seleção de um veículo já cadastrado. A API valida o vínculo, salva a ordem e retorna uma mensagem de sucesso ou erro.

4. Roteiro de demonstração

  1. Cadastre um cliente e mostre a confirmação.
  2. Consulte pelo nome, CPF ou telefone; teste também Mostrar todos e uma busca sem resultados.
  3. Cadastre um veículo selecionando o cliente; tente enviar sem proprietário para demonstrar a validação.
  4. Consulte o veículo por placa, marca ou modelo e mostre o nome do proprietário.
  5. Crie uma ordem com descrição, data e veículo; tente enviar sem escolher veículo para demonstrar que o vínculo é obrigatório.

5. Limitação conhecida

Os fluxos das cinco histórias estão implementados para demonstração local, mas a aplicação não está conectada ao MongoDB neste modo. As tarefas que exigem banco de dados real ainda dependem da integração com MongoDB; não apresente os arquivos JSON como se fossem tabelas de banco.
